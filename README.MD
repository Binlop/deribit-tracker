# Deribit Tracker

Сервис для периодического сбора цены биткоина и эфириума (`btc_usd`, `eth_usd`) с криптобиржи [Deribit](https://docs.deribit.com/) и предоставления их через REST API. [Тестовое задание](https://drive.google.com/file/d/1LRdK0s0fNCeU8K14KzzpBm6zCjXjiBd-/view)

## Стек

- **Python 3.12**
- **FastAPI** — REST API
- **SQLAlchemy 2.0** (async) + **asyncpg** — работа с PostgreSQL
- **Alembic** — миграции
- **Celery** + **Redis** — периодические задачи
- **aiohttp** — HTTP-клиент к Deribit
- **PostgreSQL 16** — хранилище данных
- **Docker / Docker Compose** — развёртывание
- **Poetry** — управление зависимостями

## Design decisions
Так таковых крупных архитектурных решений в проекте не наблюдается. Из удобного:

### 1. Разделил процессы сбора и вывода данных: API, Celery Worker + клиент + Celery beat

- Позволяет в будущем разделить масштабирование самого веб-приложения на несколько отдельных контейнеров, не затрагивая при этом получение данных от Deribit

- Несмотря на требование в 2 контейнера, было сделано 5 в силу причины выше(отдельные контейнеры для редиса, планировщика и воркера)

### 2. Слоистая архитектура внутри приложения

Код организован по доменам (`apps/prices`, `apps/deribit`), внутри домена — по слоям:

- модели
- репозитории
- сервисы
- схемы

Исключения, зависимости, домены не было смысла внедрять в архитектуру в виду малого масштаба проекта

### 3. База данных

- `price` как `Numeric`, а не `Float`

Цены — **денежные значения**. `Float` даёт погрешность (`0.1 + 0.2 != 0.3`), что для денежной единицы некорректно.

- Индекс на `(timestamp)`

Так как в задании требовалось только 2 тикера, то делать составной индекс на timestamp + ticker или на ticker не имело смысла в виде низкой вариабельности. Индекс был сделан только на timestamp


### 4. Кэширование

Все три GET-эндпоинта кэшируются:
- **TTL = 60 секунд** для согласования с частотой Celery (раз в минуту).
- **Ключи** строятся на основе всех параметры запроса.

### 5. Конфигурация через `pydantic-settings`

Все настройки — в `core/config.py` через `BaseSettings`
- Типобезопасно — `settings.database_url` имеет тип `str`.
- Валидируется — Pydantic проверит, что все обязательные поля заданы.
- Документировано - `.env.example` — это контракт окружения.

**Глобальных переменных нет.** `settings` — единственная точка входа для конфига.

## Разворачивание

### Требования

- **Docker** ≥ 24
- **Docker Compose** ≥ 2.20

### Быстрый старт

- 1. Клонировать репозиторий
```bash
git clone git@github.com:Binlop/deribit-tracker.git
```
- 2. Сменить директорию
```bash
cd deribit-tracker
```
- 3. Сборка контейнера и запуск
```bash
docker compose up --build
```

После запуска:

- **API:** http://localhost:8000
- **Swagger UI:** http://localhost:8000/docs
- **ReDoc:** http://localhost:8000/redoc
